# Kalman OU Mean Reversion — ผลการทดสอบสะสม (XAUUSD, EURUSD, NDX100)

อัปเดตล่าสุด: 2026-08-24 ใช้คู่กับ `scripts/research/kalman_walkforward.py` (รันเองได้ด้วย `python scripts/research/kalman_walkforward.py --symbol XAUUSD`)

ระบบ: Ornstein-Uhlenbeck process + Kalman filter (state = ค่าเฉลี่ยที่ปรับตัวเอง ไม่ใช่ตัวราคา) บวก Hidden Markov Model 3-state (LOW/MED/HIGH volatility) เป็นตัวกรองสภาวะตลาด บล็อกไม่ให้เข้าไม้ตอนตลาดผันผวนสูง/เป็นเทรนด์แรง

ต้นทุนที่หักในทุกการทดสอบ: 1.2 pip round-trip (Standard Account, ~0.12 หน่วยราคาทองคำ)

## ลำดับการทดลอง (เรียงตามเวลา ตัวหลังไม่ได้ดีกว่าตัวก่อนเสมอไป)

### 1. สูตรดิบจาก Quant Guild (ไม่มี risk control ใดๆ) — ❌ ล้มเหลว
ทดสอบบน M15 ทุก timeframe (M5/M15/H1): win rate ดี (58-64%) แต่ PnL เฉลี่ยต่อไม้ติดลบหรือแทบเสมอตัว — ชนะบ่อยแต่แพ้ทีขาดทุนหนัก (ไม่มี stop-loss เลยตามสูตรต้นฉบับ)

### 2. เพิ่ม Z-score stop / half-life time-stop / ATR-stop เดี่ยวๆ — ❌ แย่ลงกว่าเดิม
ทุกตัวเดี่ยวๆ (ไม่รวม regime filter) ทำให้แย่ลงกว่าไม่มี stop เลย เพราะตัด stop ก่อนที่ราคาจะกลับตัวจริงบ่อยกว่าตัดไม้ที่ไม่กลับจริง

### 3. เพิ่ม ADX regime filter — ❌ ไม่ช่วย
บล็อกช่วงเทรนด์ด้วย ADX แล้วยังแย่ทุกค่า threshold ที่ลอง

### 4. เพิ่ม Hurst exponent filter (single-scale R/S) — ⚠️ ไม่เสถียร
บาง window ดี (30, 100) บาง window แย่ (60, 150) — ไม่น่าเชื่อถือ พารามิเตอร์ไวเกินไป

### 5. เพิ่ม HMM Volatility Regime filter (Bayesian, ported จาก Quant Guild lecture 74) — ✅ ช่วยจริง
Win rate พุ่งเป็น 67.5% บน train เต็ม 3.1 ปี ขาดทุนรวมลดจาก -202 เหลือ -40.6 (เกือบเสมอตัว) — **นี่คือจุดเปลี่ยนที่แท้จริงของวันนี้**

### 6. Grid search หา k (entry) และ z_stop (cost-adjusted, train/test split 2025-07-01) — ✅ เจอ candidate แรกที่ดูดี
**k=1.7, z_stop=2.0**: PF 1.18 (train) / 1.62-1.63 (test, ทุก cost scenario) — ผ่าน PF>1.2 ครั้งแรก
**แต่**: DSR = 22.6% (train) / 51.5% (test) — ต่ำกว่าเกณฑ์ 95% มาก หลังคิด multiple-testing correction (~150 config ที่ลองมา)

### 7. เพิ่ม calib_window เป็นมิติค้นหา (60/120/240/500) — ⚠️ ดีขึ้นบาง config แต่ DSR แย่ลง
**calib=120, k=1.3, z=2.0**: PF 1.44 (train) / 1.97 (test) — ดีกว่าเดิม
**แต่**: DSR ตกไปเกือบ 0% เพราะยิ่งค้นหลายมิติ ยิ่งมีโอกาสเจอ config ที่ดูดีจากบังเอิญ (DSR ลงโทษการค้นหาที่กว้างขึ้นถูกต้องตามทฤษฎี)

### 8. Train(60%)/Validation(20%)/Test(20%) แบบเป็นทางการ, grid เบา (24 config/timeframe) — ✅ ผลดีที่สุดเท่าที่เจอ
**M5**: n=17, 1.16 ไม้/สัปดาห์, win 58.8%, PF **4.11**, **DSR 88.65%** — ใกล้ผ่านเกณฑ์ที่สุด
M15: n=5, PF 0.55, DSR 26.4% — พัง
H1: n=8, PF 1.65, DSR 0.6% — พัง
**ข้อควรระวัง**: config ที่ชนะบน validation แทบขาดทุนบน validation เอง (PF 0.96) แต่พลิกเป็น PF 4.11 บน test — อาจเป็นไม้ใหญ่บังเอิญใน test period ไม่ใช่ edge จริง

### 9. เพิ่ม Q/R sweep + 2τ time-stop + τ entry filter ตามสเปกเต็ม (grid หนาแน่นขึ้น calib_window 40-320) — ❌ แย่ลงทุกด้าน
M5: DSR ตกจาก 88.65% → **42.5%**, n เหลือแค่ 3 ไม้
M15: DSR 8.9%, n=4
H1: DSR 52.7%, n=9
**สาเหตุที่คาดว่าใช่**: τ_threshold (ตั้งเป็นครึ่งหนึ่งของ calib_window) เข้มเกินไป บล็อกโอกาสเข้าไม้จนเหลือน้อยเกินจะพิสูจน์อะไรได้เลย

### 10. ผ่อน τ_threshold ให้หลวมขึ้น (1.0/1.5/None แทน 0.5×calib_window) เฉพาะ M5 — ❌ เดาผิด ไม่ช่วย
DSR ยังต่ำอยู่ (39.65%) config ที่ชนะยังเป็น calib=320 (ไม้น้อยมาก n=3) เหมือนเดิม — **τ ไม่ใช่ตัวปัญหาจริง**

### 11. เพิ่มเงื่อนไข n≥15 บน validation ก่อนมีสิทธิ์ชนะ (ตัดกับดัก "ไม้น้อยแต่บังเอิญได้ก้อนใหญ่") — ✅✅ ผ่านเกณฑ์ครั้งแรก
พบว่าปัญหาจริงคือ**วิธีเลือก config**: การเลือกจาก net PnL รวมเพียงอย่างเดียว (ไม่สนใจ n) ชอบ config ที่มีไม้น้อยมากแต่บังเอิญโดนไม้ใหญ่ พอบังคับว่าต้องมีไม้ ≥15 ไม้บน validation ก่อนถึงจะเข้ารอบเปรียบเทียบได้:

**M5, calib=120, k=1.8, z_stop=2.8, tau=120** → TEST (one-shot): **n=22 ไม้ (1.50/สัปดาห์), win 54.5%, PF 5.96, maxDD 27.95, DSR 98.87%**

ผ่านเกณฑ์ทุกข้อยกเว้น win rate (54.5% ต่ำกว่า 55-60% นิดหน่อย) — **นี่คือผลที่ดีที่สุดของทั้งวัน** แต่ยังต้องระวัง config ที่ชนะบน validation เองขาดทุนเล็กน้อย (PF 0.95) ก่อนพลิกเป็นบวกบน test

### 12. รัน EURUSD ด้วยวิธีเดียวกับรอบ 11 (n≥15 filter) — เจอบั๊กอีกจุด แล้วแก้ + ทดสอบครบ 3 timeframe — ❌ ไม่ผ่านเกณฑ์เลย

## สรุปภาพรวม: อะไรดี อะไรไม่ดี

### ดี (ยืนยันแล้วจากหลายรอบทดสอบ)
- **HMM volatility regime filter คือของจริง** — ทุกครั้งที่เทียบ มี/ไม่มี HMM ต่างกันชัดเจนเสมอ (win rate, PF ดีขึ้นเมื่อมี)
- **M15/M5 (timeframe เล็ก) ให้ความถี่ใกล้เป้าหมายกว่า H1** เสมอ
- **Cost-aware selection (เลือก config จาก net PnL หลังหัก cost ตั้งแต่ต้น ไม่ใช่หักทีหลัง)** เปลี่ยนผลลัพธ์การค้นหาอย่างมีนัยสำคัญ — เป็น methodology ที่ถูกต้อง ควรใช้ต่อ
- **DSR (Deflated Sharpe Ratio) ทำงานตามทฤษฎี** — ยิ่งค้นหลายมิติ/หลาย config ยิ่งลงโทษแรงขึ้น ป้องกันการหลอกตัวเองได้จริง

- **เงื่อนไข "ไม้ขั้นต่ำก่อนมีสิทธิ์ชนะ" บน validation (n≥15) คือกุญแจที่แท้จริง** — ไม่ใช่ τ อย่างที่เดาไว้ก่อนหน้า ตัดกับดัก config ไม้น้อยที่บังเอิญได้ก้อนใหญ่ออกไปได้จริง

### ไม่ดี (ปัญหาที่ยังแก้ไม่ตก)
- **Sample size ยังเล็ก** (22 ไม้ในรอบที่ดีที่สุด) — ดีขึ้นจากเดิม (3-17) แต่ยังไม่ใหญ่มาก
- **Validation กับ Test มักให้ผลไม่ตรงกัน** (validation ลบ, test บวก หรือกลับกัน) — สัญญาณว่า edge ยังไม่เสถียรพอ แม้แต่ในรอบที่ดีที่สุด (รอบ 11) ก็ยังเป็นแบบนี้อยู่
- **Win rate ของ candidate ที่ดีที่สุด (54.5%) ยังต่ำกว่าเกณฑ์ 55-60% เล็กน้อย**
- **ปัญหาหลัก (frequency vs edge-survives-cost) คลี่คลายบางส่วนแล้ว** ที่ M5 — แต่ยังไม่ยืนยันซ้ำ (ยังเป็นแค่ 1 รอบทดสอบ)

## บทสรุป
**รอบที่ 11 ผ่านเกณฑ์ DSR>95% เป็นครั้งแรก** (98.87%, XAUUSD M5, calib=120 k=1.8 z=2.8 tau=120) — ความก้าวหน้าที่ใหญ่ที่สุดของวันนี้ กุญแจสำคัญคือการแก้ metric ที่ใช้เลือก config บน validation (บังคับ n≥15) ไม่ใช่การปรับ τ ตามที่เดาไว้ก่อนหน้า

**แต่พอเอาวิธีเดียวกันไปลอง EURUSD (รอบ 12) ไม่ผ่านเกณฑ์เลยสักตัว** (ดีที่สุด M15 ที่ 57.4%) — แปลว่า **ยังไม่ควรเชื่อว่ารอบ 11 คือ edge จริงที่ทำซ้ำได้** อาจเป็นคุณสมบัติเฉพาะของ XAUUSD M5 ช่วงเวลานั้น ไม่ใช่วิธีที่ generalize ข้าม asset ได้

**ทดสอบ NDX100 (asset ที่ 3) แล้วก็ไม่ผ่านเกณฑ์เช่นกัน** (ดีสุด M5 แค่ 13.4%) — ตอนนี้ยืนยันชัดเจนแล้วว่า **รอบที่ 11 (XAUUSD M5, DSR 98.87%) เป็นข้อยกเว้น ไม่ใช่คุณสมบัติทั่วไปของวิธีนี้** — ทดสอบครบ 3 asset (XAUUSD, EURUSD, NDX100) มีแค่ 1 ใน 9 การทดสอบ (asset×timeframe) เท่านั้นที่ผ่าน ตัวเลขนี้สอดคล้องกับการเป็นความบังเอิญทางสถิติมากกว่า edge จริงที่ generalize ได้

**สิ่งที่น่าสังเกต**: NDX100 M5 ให้ความถี่ดีที่สุดเท่าที่เคยเจอ (4.93 ไม้/สัปดาห์ ใกล้เป้าหมายเดิม 2-5/สัปดาห์มาก) เพียงแต่ PF (1.13) ยังไม่ถึงเกณฑ์ — อาจเป็นจุดที่ควรกลับมาจูนเพิ่มถ้าอยากได้ asset ที่ให้ทั้งความถี่และ PF พร้อมกัน (ยังไม่ได้ลองด้วยข้อมูล H1/M15 เต็มที่ backfill ไปถึงปี 2018)
