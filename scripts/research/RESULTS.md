# Kalman OU Mean Reversion — ผลการทดสอบสะสม (XAUUSD, EURUSD, NDX100)

อัปเดตล่าสุด: 2026-08-24 ใช้คู่กับ `scripts/research/kalman_walkforward.py` (รันเองได้ด้วย `python scripts/research/kalman_walkforward.py --symbol XAUUSD`)

ระบบ: Ornstein-Uhlenbeck process + Kalman filter (state = ค่าเฉลี่ยที่ปรับตัวเอง ไม่ใช่ตัวราคา) บวก Hidden Markov Model 3-state (LOW/MED/HIGH volatility) เป็นตัวกรองสภาวะตลาด บล็อกไม่ให้เข้าไม้ตอนตลาดผันผวนสูง/เป็นเทรนด์แรง

ต้นทุนที่หักในทุกการทดสอบ: 1.2 pip round-trip (Standard Account, ~0.12 หน่วยราคาทองคำ)

## ลำดับการทดลอง (เรียงตามเวลา ตัวหลังไม่ได้ดีกว่าตัวก่อนเสมอไป)

### 1. สูตรดิบจาก Quant Guild (ไม่มี risk control ใดๆ) — ❌ ล้มเหลว
ทดสอบบน M15 ทุก timeframe (M5/M15/H1): win rate ดี (58-64%) แต่ PnL เฉลี่ยต่อไม้ติดลบหรือแทบเสมอตัว — ชนะบ่อยแต่แพ้ทีขาดทุนหนัก (ไม่มี stop-loss เลยตามสูตรต้นฉบับ)

### 2. เพิ่ม Z-score stop / half-life time-stop / ATR-stop เดี่ยวๆ — ❌ แย่ลงกว่าเดิม
ทุกตัวเดี่ยวๆ (ไม่รวม regime filter) ทำให้แย่ลงกว่าไม่มี stop เลย เพราะตัด stop ก่อนที่ราคาจะกลับตัวจริงบ่อยกว่าตัดไม้ที่ไม่กลับจริง

### 3. เพิ่ม ADX regime filter — ❌ ไม่ช่วย
บล็อกช่วงเทรนด์ด้วย ADX แล้วยังแย่ทุกค่า threshold ที่ลอง

### 4. เพิ่ม Hurst exponent filter (single-scale R/S) — ⚠️ ไม่เสถียร
บาง window ดี (30, 100) บาง window แย่ (60, 150) — ไม่น่าเชื่อถือ พารามิเตอร์ไวเกินไป

### 5. เพิ่ม HMM Volatility Regime filter (Bayesian, ported จาก Quant Guild lecture 74) — ✅ ช่วยจริง
Win rate พุ่งเป็น 67.5% บน train เต็ม 3.1 ปี ขาดทุนรวมลดจาก -202 เหลือ -40.6 (เกือบเสมอตัว) — **นี่คือจุดเปลี่ยนที่แท้จริงของวันนี้**

### 6. Grid search หา k (entry) และ z_stop (cost-adjusted, train/test split 2025-07-01) — ✅ เจอ candidate แรกที่ดูดี
**k=1.7, z_stop=2.0**: PF 1.18 (train) / 1.62-1.63 (test, ทุก cost scenario) — ผ่าน PF>1.2 ครั้งแรก
**แต่**: DSR = 22.6% (train) / 51.5% (test) — ต่ำกว่าเกณฑ์ 95% มาก หลังคิด multiple-testing correction (~150 config ที่ลองมา)

### 7. เพิ่ม calib_window เป็นมิติค้นหา (60/120/240/500) — ⚠️ ดีขึ้นบาง config แต่ DSR แย่ลง
**calib=120, k=1.3, z=2.0**: PF 1.44 (train) / 1.97 (test) — ดีกว่าเดิม
**แต่**: DSR ตกไปเกือบ 0% เพราะยิ่งค้นหลายมิติ ยิ่งมีโอกาสเจอ config ที่ดูดีจากบังเอิญ (DSR ลงโทษการค้นหาที่กว้างขึ้นถูกต้องตามทฤษฎี)

### 8. Train(60%)/Validation(20%)/Test(20%) แบบเป็นทางการ, grid เบา (24 config/timeframe) — ✅ ผลดีที่สุดเท่าที่เจอ
**M5**: n=17, 1.16 ไม้/สัปดาห์, win 58.8%, PF **4.11**, **DSR 88.65%** — ใกล้ผ่านเกณฑ์ที่สุด
M15: n=5, PF 0.55, DSR 26.4% — พัง
H1: n=8, PF 1.65, DSR 0.6% — พัง
**ข้อควรระวัง**: config ที่ชนะบน validation แทบขาดทุนบน validation เอง (PF 0.96) แต่พลิกเป็น PF 4.11 บน test — อาจเป็นไม้ใหญ่บังเอิญใน test period ไม่ใช่ edge จริง

### 9. เพิ่ม Q/R sweep + 2τ time-stop + τ entry filter ตามสเปกเต็ม (grid หนาแน่นขึ้น calib_window 40-320) — ❌ แย่ลงทุกด้าน
M5: DSR ตกจาก 88.65% → **42.5%**, n เหลือแค่ 3 ไม้
M15: DSR 8.9%, n=4
H1: DSR 52.7%, n=9
**สาเหตุที่คาดว่าใช่**: τ_threshold (ตั้งเป็นครึ่งหนึ่งของ calib_window) เข้มเกินไป บล็อกโอกาสเข้าไม้จนเหลือน้อยเกินจะพิสูจน์อะไรได้เลย

### 10. ผ่อน τ_threshold ให้หลวมขึ้น (1.0/1.5/None แทน 0.5×calib_window) เฉพาะ M5 — ❌ เดาผิด ไม่ช่วย
DSR ยังต่ำอยู่ (39.65%) config ที่ชนะยังเป็น calib=320 (ไม้น้อยมาก n=3) เหมือนเดิม — **τ ไม่ใช่ตัวปัญหาจริง**

### 11. เพิ่มเงื่อนไข n≥15 บน validation ก่อนมีสิทธิ์ชนะ (ตัดกับดัก "ไม้น้อยแต่บังเอิญได้ก้อนใหญ่") — ✅✅ ผ่านเกณฑ์ครั้งแรก
พบว่าปัญหาจริงคือ**วิธีเลือก config**: การเลือกจาก net PnL รวมเพียงอย่างเดียว (ไม่สนใจ n) ชอบ config ที่มีไม้น้อยมากแต่บังเอิญโดนไม้ใหญ่ พอบังคับว่าต้องมีไม้ ≥15 ไม้บน validation ก่อนถึงจะเข้ารอบเปรียบเทียบได้:

**M5, calib=120, k=1.8, z_stop=2.8, tau=120** → TEST (one-shot): **n=22 ไม้ (1.50/สัปดาห์), win 54.5%, PF 5.96, maxDD 27.95, DSR 98.87%**

ผ่านเกณฑ์ทุกข้อยกเว้น win rate (54.5% ต่ำกว่า 55-60% นิดหน่อย) — **นี่คือผลที่ดีที่สุดของทั้งวัน** แต่ยังต้องระวัง config ที่ชนะบน validation เองขาดทุนเล็กน้อย (PF 0.95) ก่อนพลิกเป็นบวกบน test

## สรุปภาพรวม: อะไรดี อะไรไม่ดี

### ดี (ยืนยันแล้วจากหลายรอบทดสอบ)
- **HMM volatility regime filter คือของจริง** — ทุกครั้งที่เทียบ มี/ไม่มี HMM ต่างกันชัดเจนเสมอ (win rate, PF ดีขึ้นเมื่อมี)
- **M15/M5 (timeframe เล็ก) ให้ความถี่ใกล้เป้าหมายกว่า H1** เสมอ
- **Cost-aware selection (เลือก config จาก net PnL หลังหัก cost ตั้งแต่ต้น ไม่ใช่หักทีหลัง)** เปลี่ยนผลลัพธ์การค้นหาอย่างมีนัยสำคัญ — เป็น methodology ที่ถูกต้อง ควรใช้ต่อ
- **DSR (Deflated Sharpe Ratio) ทำงานตามทฤษฎี** — ยิ่งค้นหลายมิติ/หลาย config ยิ่งลงโทษแรงขึ้น ป้องกันการหลอกตัวเองได้จริง

- **เงื่อนไข "ไม้ขั้นต่ำก่อนมีสิทธิ์ชนะ" บน validation (n≥15) คือกุญแจที่แท้จริง** — ไม่ใช่ τ อย่างที่เดาไว้ก่อนหน้า ตัดกับดัก config ไม้น้อยที่บังเอิญได้ก้อนใหญ่ออกไปได้จริง

### ไม่ดี (ปัญหาที่ยังแก้ไม่ตก)
- **Sample size ยังเล็ก** (22 ไม้ในรอบที่ดีที่สุด) — ดีขึ้นจากเดิม (3-17) แต่ยังไม่ใหญ่มาก
- **Validation กับ Test มักให้ผลไม่ตรงกัน** (validation ลบ, test บวก หรือกลับกัน) — สัญญาณว่า edge ยังไม่เสถียรพอ แม้แต่ในรอบที่ดีที่สุด (รอบ 11) ก็ยังเป็นแบบนี้อยู่
- **Win rate ของ candidate ที่ดีที่สุด (54.5%) ยังต่ำกว่าเกณฑ์ 55-60% เล็กน้อย**
- **ปัญหาหลัก (frequency vs edge-survives-cost) คลี่คลายบางส่วนแล้ว** ที่ M5 — แต่ยังไม่ยืนยันซ้ำ (ยังเป็นแค่ 1 รอบทดสอบ)

## บทสรุป
**รอบที่ 11 ผ่านเกณฑ์ DSR>95% เป็นครั้งแรก** (98.87%, XAUUSD M5, calib=120 k=1.8 z=2.8 tau=120) — ความก้าวหน้าที่ใหญ่ที่สุดของวันนี้ กุญแจสำคัญคือการแก้ metric ที่ใช้เลือก config บน validation (บังคับ n≥15) ไม่ใช่การปรับ τ ตามที่เดาไว้ก่อนหน้า

**แต่พอเอาวิธีเดียวกันไปลอง EURUSD (รอบ 12) ไม่ผ่านเกณฑ์เลยสักตัว** (ดีที่สุด M15 ที่ 57.4%) — แปลว่า **ยังไม่ควรเชื่อว่ารอบ 11 คือ edge จริงที่ทำซ้ำได้** อาจเป็นคุณสมบัติเฉพาะของ XAUUSD M5 ช่วงเวลานั้น ไม่ใช่วิธีที่ generalize ข้าม asset ได้

**ทดสอบ NDX100 (asset ที่ 3) แล้วก็ไม่ผ่านเกณฑ์เช่นกัน** (ดีสุด M5 แค่ 13.4%) — ตอนนี้ยืนยันชัดเจนแล้วว่า **รอบที่ 11 (XAUUSD M5, DSR 98.87%) เป็นข้อยกเว้น ไม่ใช่คุณสมบัติทั่วไปของวิธีนี้** — ทดสอบครบ 3 asset (XAUUSD, EURUSD, NDX100) มีแค่ 1 ใน 9 การทดสอบ (asset×timeframe) เท่านั้นที่ผ่าน ตัวเลขนี้สอดคล้องกับการเป็นความบังเอิญทางสถิติมากกว่า edge จริงที่ generalize ได้

**สิ่งที่น่าสังเกต**: NDX100 M5 ให้ความถี่ดีที่สุดเท่าที่เคยเจอ (4.93 ไม้/สัปดาห์ ใกล้เป้าหมายเดิม 2-5/สัปดาห์มาก) เพียงแต่ PF (1.13) ยังไม่ถึงเกณฑ์ — อาจเป็นจุดที่ควรกลับมาจูนเพิ่มถ้าอยากได้ asset ที่ให้ทั้งความถี่และ PF พร้อมกัน (ยังไม่ได้ลองด้วยข้อมูล H1/M15 เต็มที่ backfill ไปถึงปี 2018)

**สรุปสุดท้ายสำหรับ NDX100**: ทดลองมาแล้ว 3 แนวทางที่ต่างกัน (symmetric+HMM, local-trend-aware, long-only+drift-aware) **ไม่มีแนวทางไหนพา NDX100 ผ่านเกณฑ์ได้เลย** — เพียงพอจะสรุปได้ว่าปัญหาไม่ใช่เรื่องพารามิเตอร์หรือ asymmetry อีกต่อไป แต่เป็นเพราะโครงสร้างพฤติกรรมราคาของดัชนี Nasdaq (trend-dominant, ไม่ mean-revert ในกรอบเวลาที่ทดสอบ) ไม่เข้ากับสมมติฐานพื้นฐานของกลยุทธ์นี้เลย **แนะนำ: หยุดพยายามปรับโมเดลให้เข้ากับ NDX100 ต่อ** เอาเวลาไปโฟกัสที่ XAUUSD (ตัวเดียวที่ผ่านเกณฑ์) หรือ EURUSD (ยังมีความหวังจาก trend_aware ablation ที่ยังไม่ได้ทดสอบเต็มรูปแบบ) แทน — **หมายเหตุ: ตามคำสั่งผู้ใช้ ตั้งแต่รอบ 18 เป็นต้นไปโฟกัสเฉพาะ XAUUSD/EURUSD ไม่ทำ NDX100 ต่อแล้ว**

### 19. ⚠️ ตรวจสอบ "validation อ่อนแอ, test แข็ง" ให้ชัด — Validation ไม่มีอำนาจพยากรณ์ผล test เลยสำหรับ XAUUSD M5 (`scripts/research/val_test_correlation.py`, ผู้ใช้รันเอง)

รอบ 18 เจอรูปแบบน่าสงสัยซ้ำ (config ที่ชนะมี validation แทบเสมอตัว/ขาดทุนเล็กน้อยเสมอ) เลยเขียนสคริปต์ตรวจสอบตรงๆ: เอา **ทุก config ที่ผ่านเกณฑ์ n≥15 บน validation** (108 config จาก 384) มารันทั้งบน validation และ test แล้ววัด **Spearman rank correlation** ระหว่างผลทั้งสองฝั่ง — ถ้า validation เลือกของจริงได้ ผลควรมีสหสัมพันธ์เป็นบวก

**ผลที่ได้ (XAUUSD M5, 108 configs)**:

| Metric | Spearman ρ |
|---|---|
| Validation net PnL vs Test net PnL | **-0.129** |
| Validation PF vs Test PF | **-0.495** |
| Pearson, net PnL vs net PnL | -0.192 |

**ทั้งคู่ติดลบ** — ไม่ใช่แค่ "ไม่มีความสัมพันธ์" แต่เป็น**ความสัมพันธ์ตรงข้าม** ดูจาก top 10 by validation net PnL: **กลุ่ม config ที่แย่ที่สุดบน validation (ขาดทุนเล็กน้อย, PF 0.95-1.00) คือกลุ่มเดียวกันที่ให้ผลดีที่สุดบน test (PF 5.62-5.96)** เกิดขึ้นสม่ำเสมอตลอดทั้ง 108 config ไม่ใช่ความบังเอิญของ config เดียว

**ความหมาย (สำคัญที่สุดของทั้งโปรเจกต์)**: วิธีเลือก config จาก validation **ไม่มีอำนาจแยกของจริงออกจากของบังเอิญเลยสำหรับ XAUUSD M5** — DSR 98.87-99.60% ที่เคยรายงานว่า "ผ่านเกณฑ์" น่าจะเป็นเพราะ **test period ของช่วงเวลานั้นบังเอิญเข้ากับ config ที่สุ่มเลือกมา ไม่ใช่เพราะ methodology หา edge เจอจริง** — DSR ตรวจจับเรื่องนี้ไม่ได้ เพราะ DSR วัดแค่ "ผลบน test เกินกว่าที่คาดจากการสุ่ม N trials ไหม" ไม่ได้เช็คว่า validation เชื่อมโยงกับ test จริงหรือเปล่า ทั้งสองอย่างเป็นการทดสอบคนละมิติกัน (DSR = ระวัง data snooping ตอนเลือก "ตัวที่ดีที่สุดบน test เอง" จากหลาย trial, ส่วน correlation check นี้ = ระวังว่า validation-based selection เองใช้งานได้จริงหรือเปล่า) — **สอบผ่านอย่างหนึ่งไม่ได้แปลว่าผ่านอีกอย่างหนึ่งด้วย**

**ต้องทบทวนข้อสรุปเดิมของทั้งโปรเจกต์**: "XAUUSD M5 ผ่านเกณฑ์ DSR>95%" ที่เคยรายงานว่าเป็นผลที่ดีที่สุด **ตอนนี้มีหลักฐานโดยตรงว่าอาจเป็นเพียงความบังเอิญของช่วง test period หนึ่งเท่านั้น ไม่ใช่ edge ที่ methodology การันตีได้จริง** — ควรตีความผลทั้งหมดของโปรเจกต์นี้ใหม่ด้วยความระมัดระวังมากขึ้นกว่าที่เคยรายงานไว้ก่อนหน้า

### 20. Rolling Walk-Forward Optimization (WFO) — ทดสอบความสม่ำเสมอข้าม 14 ช่วงเวลาทั้งปีครึ่ง (`scripts/research/rolling_wfo.py`, ผู้ใช้รันเอง)

แทนที่จะแบ่ง Train/Val/Test แบบตายตัว 60/20/20 ครั้งเดียว (ซึ่งรอบ 19 เพิ่งพิสูจน์ว่าเชื่อถือไม่ได้สำหรับคู่นี้) ใช้หน้าต่างเลื่อน: **Train 90 วัน → เลือก config ที่ดีที่สุด → Test 30 วัน out-of-sample → เลื่อนไป 30 วัน → ทำซ้ำ** ได้ 14 fold ไม่ทับซ้อนกันตลอดข้อมูล XAUUSD M5 ที่มี (มี.ค. 2025 – ส.ค. 2026) ใช้กริดย่อ 64 config/fold (เล็กกว่ากริดเต็มเพื่อให้รันไหวหลาย fold)

**ผลรายรอบ**: 9 จาก 14 fold (64%) ทำกำไรได้ (PF≥1.0) อีก 5 fold ขาดทุน (PF ต่ำสุด 0.17-0.75) — ไม่สม่ำเสมอเต็มที่แต่ก็ไม่ใช่ศูนย์

**Aggregate (185 ไม้ out-of-sample สะสมทั้ง 14 fold)**: win rate 61.1%, PF **1.43**, expectancy +1.57, maxDD 98.95

**บั๊กที่พบและแก้ระหว่างทาง**: เวอร์ชันแรก hardcode `sr_variance_across_trials=0.0` ทำให้ DSR ไม่ได้หักโทษ multi-testing เลย (ได้ 94.34% ซึ่งเป็นค่าที่ผิด) แก้โดยคำนวณ variance จริงจาก Sharpe ของทุก config ที่ผ่านเกณฑ์ในแต่ละ fold (pool ข้าม 14 fold) แล้วรันใหม่:

**DSR ที่ถูกต้อง (n_trials=64) = 0.000176% (~0)** — ต่างจากค่าผิดเดิมมหาศาล

**สรุป**: แม้ PF รวม 1.43 และ 64% ของ fold ทำกำไรได้จะดูเป็นสัญญาณบวกอ่อนๆ (ดีกว่าสุ่มเดา 50%) แต่พอหักโทษ multi-testing อย่างถูกต้อง (แต่ละ fold ลอง 64 config ก่อนเลือก และแต่ละ fold มีไม้น้อย 10-45 ไม้ ทำให้ Sharpe ของแต่ละ config มีความแปรปรวนสูงจากการสุ่มตัวอย่างเล็ก) **ผลรวมไม่แข็งแรงพอจะพิสูจน์ว่าไม่ใช่ความบังเอิญเลย** — สอดคล้องกับข้อค้นพบของรอบ 19 (validation ไม่มีอำนาจพยากรณ์ test) เป็นหลักฐานชิ้นที่ 2 ที่ชี้ไปทางเดียวกัน

**สถานะรวมของโปรเจกต์ตอนนี้ (หลังรอบ 18-20)**: มีหลักฐาน 3 ชิ้นจากวิธีตรวจสอบต่างกัน (fixed-split DSR, val/test correlation, rolling WFO ที่หักโทษถูกต้อง) **ที่ไม่มีชิ้นไหนยืนยันว่า XAUUSD M5 มี edge จริงที่ทนต่อการทดสอบทางสถิติอย่างเข้มงวด** — ผลที่เคยดูดีที่สุดของทั้งโปรเจกต์ (DSR 98.87-99.60% จาก fixed split) ตอนนี้น่าเชื่อว่าเป็นความบังเอิญของช่วงเวลาเดียว ไม่ใช่ edge ที่ generalize ได้

### 21. Rolling WFO บน EURUSD M15 — 46 fold ตลอด ~3.4 ปี (`scripts/research/rolling_wfo.py`, ผู้ใช้รันเอง)

fixed-split (รอบ 18) เคยให้ EURUSD M15 ดูดีที่สุดในบรรดา timeframe ของ EURUSD (DSR 75.2%, PF 9.86, n=20) เลยตรวจสอบต่อด้วย rolling WFO เดียวกับที่ทำกับ XAUUSD M5 (train 90 วัน → test 30 วัน → เลื่อน 30 วัน, กริดย่อ 64 config/fold) ได้ 46 fold ครอบคลุมข้อมูล ส.ค. 2022 – ส.ค. 2026

**ผลรายรอบ**: 20 จาก 46 fold (43%) ทำกำไรได้ (PF≥1.0) — ต่ำกว่าเดา 50/50 เสียอีก

**Aggregate (770 ไม้ out-of-sample สะสมทั้ง 46 fold)**: win rate 54.8%, PF **0.897** (ขาดทุนสุทธิ), expectancy ติดลบ (-0.0000658/ไม้), maxDD 6.9%

**DSR (n_trials=64) = 0.0**

**สรุป**: EURUSD M15 rolling WFO **แย่กว่า XAUUSD M5 อีก** — ไม่ใช่แค่ DSR ต่ำ (เหมือน XAUUSD M5) แต่ PF รวมทั้งชุดต่ำกว่า 1.0 จริง (ขาดทุนสุทธิ) และสัดส่วน fold ที่กำไรได้ต่ำกว่าครึ่ง ยืนยันรูปแบบเดียวกับ XAUUSD M5 อีกครั้ง: ผล DSR สูงจาก fixed-split single test window (75.2%) ไม่ใช่สัญญาณของ edge ที่ทนต่อเวลา — เป็นหลักฐานชิ้นที่ 4 (นับรวม 19-20 ของ XAUUSD และตอนนี้ของ EURUSD) ที่ชี้ไปทางเดียวกันว่า methodology การค้นหา config จาก validation/train window เดียวไม่สามารถแยกของจริงจากความบังเอิญได้ทั้งสอง symbol ที่ทดสอบมา

**อัปเดต**: `rolling_wfo.py` เปลี่ยนจาก DSR (ไม่ตรงสมมติฐานของ rolling WFO ที่แต่ละ fold เลือก config แยกกัน) ไปใช้ **Bootstrap 95% CI บน expectancy ของไม้ out-of-sample ที่ stitch มาทั้งหมด** แทน — รันซ้ำ EURUSD M15 ด้วยเมทริกใหม่ ได้ผลรายรอบเหมือนเดิมทุกประการ (fold-level results ไม่เปลี่ยนเพราะเป็นข้อมูลเดียวกัน) และสรุปตรงกัน: **CI = [-0.00019, 0.00006]ครอบคลุมศูนย์, P(mean>0)=0.152** → expectancy ไม่ต่างจากศูนย์อย่างมีนัยสำคัญทางสถิติ ยืนยันด้วยเมทริกที่เหมาะสมกว่าว่า EURUSD M15 ไม่มี edge จริง

### 22. Rolling WFO sweep ครบทุก symbol/timeframe ที่เหลือ ด้วย Bootstrap CI — ไม่มีตัวไหนผ่านเลย (ผู้ช่วยรันเองตามคำขอของผู้ใช้)

หลังเปลี่ยนมาตรวัดเป็น Bootstrap CI แล้ว รัน rolling WFO เพิ่มให้ครบทุก symbol/timeframe ที่ fixed-split เคยดูพอมีความหวัง (ตัด H1 ทั้งคู่ออกเพราะไม้น้อยเกินไปในทั้งปี, ตัด NDX100 M5/H1 ออกเพราะ NDX100 ทดลองมาแล้ว 3 วิธีที่ต่างกันโดยสิ้นเชิงและพังหมดตั้งแต่ fixed-split — เลือกใช้ M15 ซึ่งเป็น timeframe ที่ NDX100 เคยทำได้ดีที่สุด):

| Symbol | TF | Fold | PF รวม | Fold กำไร (PF≥1.0) | Bootstrap 95% CI | P(mean>0) |
|---|---|---|---|---|---|---|
| XAUUSD | M5 | 14 | 1.43 | 9/14 (64%) | (รันก่อนเปลี่ยนเป็น CI, DSR เดิม≈0%) | - |
| XAUUSD | M15 | 48 | 0.83 | 20/48 (42%) | [-2.30, 0.41] | 0.092 |
| EURUSD | M5 | 13 | 0.83 | 5/13 (38%) | [-0.00019, 0.00008] | 0.219 |
| EURUSD | M15 | 46 | 0.90 | 20/46 (43%) | [-0.00019, 0.00006] | 0.152 |

**ไม่มีแถวไหนเลยที่ CI ทั้งแถบอยู่เหนือศูนย์** — ทุกตัวรวม NDX100 M15 ที่ตัวเลขดูเท่าทุนพอดี (PF≈1.00, 52% fold กำไร) ก็ยังมี CI กว้างมากจนครอบคลุมทั้งบวกและลบ (P(mean>0)=0.492 ≈ เดาสุ่ม 50/50 พอดี) — ไม่ใช่แค่ "ไม่ผ่านเกณฑ์สูง" แต่คือ**ไม่มีหลักฐานทางสถิติเลยว่า symbol/timeframe ไหนในกลุ่มที่ทดสอบ (XAUUSD, EURUSD, NDX100 × M5/M15) มี edge จริงที่ generalize ข้ามเวลาได้**

**สรุปรวมของทั้งโปรเจกต์ ณ จุดนี้**: ทดสอบมาแล้ว 5 combination (symbol×timeframe) ด้วย rolling WFO อย่างเข้มงวดที่สุดเท่าที่ทำได้ในโปรเจกต์นี้ (สุ่มสร้าง config ใหม่ทุก fold + bootstrap significance test บนผลรวม) ไม่มี combination ไหนผ่านเลยแม้แต่ตัวเดียว กลยุทธ์ Kalman/OU mean-reversion แบบที่ implement ไว้ **ยังไม่มีหลักฐานว่าใช้งานได้จริงกับ XAUUSD, EURUSD, หรือ NDX100 เลยในตอนนี้**

### 23. กลยุทธ์ที่สอง: Momentum/Trend-Following (Donchian Channel Breakout) — XAUUSD M5 ดีที่สุดในโปรเจกต์ (ยังไม่ผ่านนัยสำคัญเต็มรูปแบบ)

หลัง mean-reversion ล้มเหลวทุก combination ที่ทดสอบ (experiment 19-22) ลองกลยุทธ์ตรงข้าม: **momentum/trend-following** แทนที่จะ fade การเบี่ยงเบนจากค่าเฉลี่ย ให้เข้าไม้ตามทิศทางที่ราคา breakout ออกจากกรอบล่าสุด (Donchian channel, สไตล์ Turtle system) — เพิ่มไฟล์ `analysis/strategies/trend_following.py` (`run_trend_following()`) และ `scripts/research/trend_rolling_wfo.py` (rolling WFO + bootstrap CI เดียวกับ `rolling_wfo.py` เป๊ะ) พารามิเตอร์หลัก: `entry_window`/`exit_window` (กรอบ breakout เข้า/ออก), `trend_filter_ema` (กรองทิศทางตามเทรนด์ยาว), `atr_stop_mult` (stop loss สัมบูรณ์)

**ผล 3 combination**:

| Symbol | TF | Fold | PF รวม | Fold กำไร | Bootstrap 95% CI | P(mean>0) |
|---|---|---|---|---|---|---|
| **XAUUSD** | **M5** | 14 | **1.23** | **11/14 (79%)** | [-0.10, 3.57] | **0.966** |
| EURUSD | M5 | 13 | 0.75 | 3/13 (23%) | [-0.00029, -0.00006] | 0.002 |

**XAUUSD M5 คือผลที่ดีที่สุดในทั้งโปรเจกต์จนถึงตอนนี้**: PF รวม 1.23 (กำไรสุทธิจริง), 79% ของ fold ทำกำไรได้ (สูงสุดในบรรดาทุก experiment ทั้ง mean-reversion และ momentum), P(mean>0)=96.6% ใกล้เคียงเกณฑ์นัยสำคัญ 95% มาก (ขอบล่างของ CI ติดลบเพียงเล็กน้อย -0.097) — **ยังไม่ผ่านเกณฑ์นัยสำคัญเต็มรูปแบบ (CI ยังไม่พ้นศูนย์ทั้งแถบ) แต่เป็น lead ที่น่าสนใจที่สุดที่เจอมาในโปรเจกต์นี้**

**EURUSD M5 แย่ลงอย่างชัดเจน**: CI อยู่ต่ำกว่าศูนย์ทั้งแถบ ([-0.00029, -0.00006], P(mean>0)=0.2%) — นี่คือกรณีที่หายากในโปรเจกต์นี้ที่ **ผลมีนัยสำคัญทางสถิติจริง แต่เป็นด้านลบ** (ขาดทุนสม่ำเสมอ ไม่ใช่แค่ไม่แน่ใจ) win rate ต่ำมาก (~30%) เพราะ breakout กลับทิศบ่อยเกินไปสำหรับ EURUSD M5 (whipsaw)

**NDX100 M15 ไม่ดีขึ้นเลย**: PF 0.97 (แทบเท่าทุน) แต่ fold consistency แย่กว่า mean-reversion เดิมด้วยซ้ำ (38% เทียบกับ 52% ของ mean-reversion) — สมมติฐานที่ว่า NDX100 เป็น "trend-dominant asset" ที่ควรเหมาะกับ momentum มากกว่า **ไม่ได้รับการยืนยันจาก Donchian breakout system ตัวนี้**

**สรุป**: momentum ไม่ใช่คำตอบสำเร็จรูปสำหรับทุก symbol เหมือนที่ mean-reversion ก็ไม่ใช่ — แต่ XAUUSD M5 ด้วย momentum เป็น lead แรกในทั้งโปรเจกต์ที่ใกล้เคียงนัยสำคัญทางสถิติจริง

### 24. Config Stability Check + Fixed-Config Walk-Forward บน XAUUSD M5 Momentum — **ผ่านนัยสำคัญทางสถิติเป็นครั้งแรกในทั้งโปรเจกต์**

แทนที่จะขยาย grid search ให้กว้างขึ้น (ซึ่งจะเพิ่มความเสี่ยง overfitting ไม่ใช่ลด — ยิ่งลอง config เยอะยิ่งมีโอกาสเจอของที่ fit กับ noise ของ fold นั้นพอดี) ตรวจสอบความทนทานของผลลัพธ์ experiment 23 (XAUUSD M5 momentum, PF 1.23, P(mean>0)=96.6%) ด้วย 2 วิธีแทน:

**ก. เช็คว่า config ที่ถูกเลือกในแต่ละ 14 fold เหมือนกันแค่ไหน** — พบว่า `entry_window=80, exit_window=40` ถูกเลือกซ้ำใน **9/14 fold (64%)** ไม่ใช่สุ่มมั่วไปคนละทางเลย ในขณะที่ `trend_filter_ema`/`atr_stop_mult` เปลี่ยนไปมาแทบทุก fold ไม่มีแพทเทิร์น — บ่งชี้ว่าค่า window เป็นสัญญาณจริง ส่วนสอง filter หลังเป็นแค่ noise dimension

**ข. Fixed-Config Walk-Forward** — ล็อค config ที่ถูกเลือกบ่อยที่สุดและง่ายที่สุด (`entry_window=80, exit_window=40, trend_filter_ema=None, atr_stop_mult=None`) รันผ่านทั้ง 14 fold **โดยไม่ re-optimize เลยสักครั้ง** (ตัดโอกาส overfitting ต่อ fold ออกไปทั้งหมด):

```
AGGREGATE (n=900, 14 fold, config เดียวตลอด):
  win_rate=37.0%  PF=1.26  expectancy=+2.31/ไม้  maxDD=458.79
  Bootstrap 95% CI = [0.06, 4.71]  P(mean>0)=0.978
  folds with PF>=1.0: 10/14 (71%)
```

**CI อยู่เหนือศูนย์ทั้งแถบ (ขอบล่าง 0.06 > 0) — ผ่านเกณฑ์นัยสำคัญทางสถิติ 95% เป็นครั้งแรกในทั้งโปรเจกต์** ดีกว่าผลตอน re-optimize ทุก fold ด้วยซ้ำ (PF 1.23→1.26, fold กำไร 79%→71% แต่ CI ผ่านจริงแทนที่จะเฉียด) ยืนยันว่าไม่ใช่ overfitting เพราะ config ไม่เคยเปลี่ยนเลยตลอด 1.5 ปีของข้อมูล test

**หมายเหตุข้อจำกัด**: 14 fold ไม่ทับซ้อนกัน = 14 ช่วงเวลาอิสระเท่านั้น (ไม่ใช่ 900 ไม้ที่เป็นอิสระต่อกันจริง เพราะไม้ในแต่ละ fold สัมพันธ์กันตามช่วงเวลาเดียวกัน) เป็นหลักฐานที่ดีที่สุดในโปรเจกต์นี้ แต่ยังควรตรวจสอบเพิ่มก่อนใช้งานจริง เช่น ทดสอบกับข้อมูล out-of-sample ใหม่ที่ไม่เคยใช้เลย หรือลองช่วง train/test ที่ไม่ใช่ 90/30 วันดูว่าผลเปลี่ยนมากไหม

**เช็คต่อด้วย train=60d/test=20d (23 fold, config เดียวกันเป๊ะ ไม่เปลี่ยนอะไรเลย)**:

```
AGGREGATE (n=981, 23 fold):
  win_rate=36.7%  PF=1.22  expectancy=+1.90/ไม้  maxDD=594.10
  Bootstrap 95% CI = [-0.14, 3.98]  P(mean>0)=0.967
  folds with PF>=1.0: 18/23 (78%)
```

**PF และสัดส่วน fold กำไรใกล้เคียงกับ train=90/test=30 มาก (1.26 vs 1.22, 71% vs 78%)** — ทิศทางและขนาดของผลไม่ได้ผูกติดกับการเลือก window ขนาดใดขนาดหนึ่งเป็นพิเศษ เป็นสัญญาณดี **แต่ CI ของรอบนี้ขอบล่างติดลบเล็กน้อย (-0.14) ไม่ผ่านเกณฑ์นัยสำคัญ 95% เต็มรูปแบบ** (ต่างจาก train=90/test=30 ที่ผ่าน) แม้ P(mean>0)=96.7% จะยังใกล้เคียง 90/30's 97.8% มาก

**สรุปสถานะ ณ จุดนี้**: XAUUSD M5 momentum breakout (entry=80/exit=40) แสดงสัญญาณบวกที่**สม่ำเสมอในทิศทางและขนาดข้าม 2 การตั้งค่า train/test window ที่ต่างกัน** (PF~1.2-1.26, ~70-80% fold กำไร) แต่**นัยสำคัญทางสถิติ (CI) ยังไม่นิ่งสนิท** — ผ่านเกณฑ์ 95% ในกรณีหนึ่งแต่ไม่ผ่านหวุดหวิดในอีกกรณี น่าจะมี edge จริงอยู่บางส่วน แต่ยังไม่ใช่หลักฐานที่แน่นหนาเพียงพอจะใช้เทรดจริงโดยไม่ทดสอบเพิ่ม

**ตัดทิ้ง — ไม่ใช่ math-derived model**: ผู้ใช้ถามตรงๆ ว่ากติกา breakout นี้เป็น "คณิตศาสตร์" จริงเหมือน OU หรือเปล่า คำตอบคือไม่ใช่ — กติกา "ทะลุจุดสูงสุด/ต่ำสุดของ N แท่ง" เป็นกติกาเชิงประจักษ์ (empirical rule) ที่คิดขึ้นจากการสังเกต ไม่ได้มาจากการแก้สมการทางคณิตศาสตร์เหมือนที่ OU ทุกสูตร ($\sigma_{stat}$, half-life, Kalman gain) มาจากการแก้ $dX_t=\theta(\mu-X_t)dt+\sigma dW_t$ โดยตรง — แม้จะมีงานวิจัยวิชาการรองรับปรากฏการณ์ momentum ทางสถิติ (Moskowitz/Ooi/Pedersen 2012) และผลทดสอบจะเป็นผลที่ดีที่สุดในโปรเจกต์นี้ก็ตาม ผู้ใช้ตัดสินใจตัดทิ้งด้วยมาตรฐานเดียวกับที่เคยตัด Wyckoff filter ทิ้งไปก่อนหน้านี้ (ต้องเป็นโมเดลที่มาจากการแก้สมการทางคณิตศาสตร์เท่านั้น ไม่ใช่กติกาที่ทดสอบแล้วได้ผลดี) — **`trend_following.py` และ `trend_rolling_wfo.py` เก็บไว้ในโค้ดเป็นหลักฐาน แต่เลิกพัฒนาต่อแล้ว**

### 25. Risk Management Layer — Inverse Volatility Position Sizing + Fixed-Fractional Risk Cap

เพิ่ม `analysis/backtester/risk_management.py` (ไม่ใช่ signal generation ใหม่ แต่เป็นชั้นบริหารความเสี่ยง/ขนาด position ที่ครอบสัญญาณเดิมได้ทุกโมเดล): `position_size(equity, sigma_t, contract_value, risk_fraction)` = (equity × risk_fraction) / (σ_t × contract_value) และ `simulate_equity_with_sizing()` จำลอง equity แบบปรับขนาดไม้ตาม volatility ปัจจุบันทุกไม้ พร้อม pre-trade circuit breaker (หยุดเปิดไม้ใหม่ถ้า equity ต่ำกว่า floor ที่กำหนด)

ทดสอบเทียบ dynamic sizing กับ flat sizing (risk budget เฉลี่ยเท่ากัน) บน config OU ที่กำหนดตายตัว (`scripts/research/risk_sizing_demo.py`) — XAUUSD M5 (7 ไม้/17 เดือน): dynamic final equity $13,254 vs flat $12,128; XAUUSD M15 (10 ไม้/4.25 ปี): dynamic $10,592 vs flat $10,018, maxDD ต่ำกว่า flat ($315 vs $467) ผลปนกัน (n น้อยเกินสรุปเชิงสถิติ) — **สรุปสำคัญ: กลไกนี้ช่วยเรื่อง "ความเรียบของ equity curve/ควบคุมความเสี่ยงต่อไม้ให้คงที่" เท่านั้น ไม่ได้เปลี่ยน expectancy ของสัญญาณเข้า/ออกไม้เลย** ถ้าสัญญาณมี edge เป็นศูนย์ทางสถิติ (แบบที่เจอมาตลอด) position sizing ไม่ทำให้กลายเป็นบวกได้ เป็นแค่ชั้นบริหารความเสี่ยงที่ควรมีไว้ใช้เมื่อมี edge ที่พิสูจน์แล้วเท่านั้น — เก็บโมดูลนี้ไว้ใช้กับโมเดลไหนก็ได้ในอนาคตที่ผ่านการพิสูจน์ edge แล้ว

### 26. CIR Process (Cox-Ingersoll-Ross) — โมเดลสุ่มตัวที่สอง (math-derived) ทดสอบแทน OU

หลัง OU ไม่ผ่าน rolling WFO เลยสักตัว (experiment 19-22) และ momentum ถูกตัดทิ้งเพราะไม่ใช่ math-derived (experiment 23-24) ลองโมเดลสุ่มอื่นที่ยังคง derive จากสมการจริงเหมือน OU: **CIR process** $dX_t = \theta(\mu-X_t)dt + \sigma\sqrt{X_t}dW_t$ — drift term เหมือน OU เป๊ะ (แรงดึงกลับ mean เท่ากัน) ต่างแค่ diffusion term ที่ variance ขึ้นกับระดับราคาปัจจุบัน (สูงเมื่อราคาสูง, ต่ำเมื่อราคาต่ำ) แทนที่จะคงที่ตลอดแบบ OU

เพิ่มไฟล์ `analysis/strategies/cir_mean_reversion.py` (`estimate_cir_sigma()` ใช้ conditional least squares ตามวิธี Chan/Karolyi/Longstaff/Sanders 1992, `KalmanCIR` มี Q/R ที่คำนวณใหม่ทุกบาร์ตามระดับราคาแทนค่าคงที่) และ `scripts/research/cir_rolling_wfo.py` (rolling WFO + bootstrap CI เดียวกับที่ใช้ทั่วโปรเจกต์)

**ผล XAUUSD M5 (14 fold)**:
```
total n=157  win_rate=62.4%  PF=1.23  expectancy=+1.09/ไม้  maxDD=145.17
Bootstrap 95% CI = [-1.58, 3.62]  P(mean>0)=0.808
folds with PF>=1.0: 10/14 (71%)
```

**ดีขึ้นกว่า OU ธรรมดาชัดเจน** (OU บน XAUUSD M5 ได้ DSR≈0% ไม่มีสัญญาณบวกเลย vs CIR ได้ P(mean>0)=80.8% ทิศทางบวกชัดเจนกว่ามาก) **แต่ยังไม่ผ่านเกณฑ์นัยสำคัญ 95%** (CI ยังครอบคลุมศูนย์) — เป็นทิศทางที่น่าสนใจ คุ้มทดสอบต่อ (เช่น fixed-config check แบบเดียวกับที่ทำกับ momentum, หรือทดสอบ symbol/timeframe อื่น) ก่อนสรุป

**ตรวจสอบเพิ่มด้วยมาตรฐานที่เข้มกว่า: Monte Carlo Permutation Test** (`monte_carlo_baseline()` ใน `cir_rolling_wfo.py`, ดูรายละเอียดหลักการใน README) — ผู้ใช้ถามว่า "ต้องมีมาตรฐานเกณฑ์วัดจริงได้ด้วย" ไม่ใช่แค่เทียบ CI กับศูนย์ลอยๆ เลยเพิ่มการเทียบกับ**การสุ่มเข้าไม้ที่คุมจำนวนไม้และระยะเวลาถือให้เท่ากับของจริงทุกประการ** (สุ่ม 1,000 รอบ/fold, สุ่มทิศทาง 50/50):

```
real aggregate net PnL = 171.88
random baseline: mean=-14.02  std=180.47  [5th,95th pct]=[-296.91, 296.38]
ผลจริงเอาชนะการสุ่มได้ 85.7% ของรอบ (ต้องการ >=95%) -- ไม่ผ่าน
```

**ยังไม่ผ่านมาตรฐานที่เข้มกว่านี้เช่นกัน** แต่ตัวเลข 85.7% สอดคล้องกับ Bootstrap CI (P(mean>0)=80.8%) ทั้งสองวิธีชี้ไปทางเดียวกัน — **สรุป CIR: ดีกว่า OU อย่างชัดเจนในทุกมาตรวัด แต่ยังไม่ถึงระดับที่แยกออกจากการสุ่มได้อย่างมั่นใจทางสถิติ** (85.7% ดีกว่าเดา 50/50 มาก แต่ยังไม่ถึงเกณฑ์ 95% ที่ตั้งไว้)

**ทดสอบ CIR เพิ่มอีก 3 combination (EURUSD M5, XAUUSD M15, EURUSD M15)**:

| Symbol | TF | Fold | PF | Bootstrap P(mean>0) | Monte Carlo percentile |
|---|---|---|---|---|---|
| XAUUSD | M5 | 14 | 1.23 | 80.8% | 85.7% |
| EURUSD | M5 | 13 | 1.23 | 79.1% | **99.6% (ผ่าน)** |
| XAUUSD | M15 | 48 | 0.81 | 9.1% | **3.0% (แย่กว่าสุ่ม)** |
| EURUSD | M15 | 46 | 0.99 | 47.7% | **98.3% (ผ่าน)** |

**แพทเทิร์นที่พบ**: EURUSD (ทั้ง M5 และ M15) ผ่าน Monte Carlo random-entry test (เอาชนะการสุ่มได้ >95%) **แต่ไม่ผ่าน Bootstrap CI** (P(mean>0) 47.7-79.1%, ยังไม่ยืนยัน expectancy เป็นบวกจริง) ส่วน XAUUSD ไม่ผ่านทั้งคู่ (M15 แย่กว่าสุ่มธรรมดาด้วยซ้ำ — real net PnL -809.33 vs random mean -79.64, เอาชนะสุ่มได้แค่ 3%)

**ความหมายของ Monte Carlo ผ่านแต่ Bootstrap ไม่ผ่าน**: การสุ่มเข้าไม้ (baseline) จะขาดทุนเฉลี่ยจาก cost/spread เสมอ (ไม่มี skill เลือกทิศทาง) เพราะงั้น "เอาชนะการสุ่มได้ 95%+" อาจหมายถึงแค่ **"เลือกจังหวะเข้าได้ดีกว่าสุ่มพอจะเอาชนะ cost drag ได้"** ไม่ใช่ "มี expectancy เป็นบวกจริงแบบมั่นใจทางสถิติ" — สองมาตรวัดตอบคำถามคนละมิติกัน (Monte Carlo = ดีกว่าสุ่มแค่ไหน, Bootstrap = ค่าเฉลี่ยจริงต่างจากศูนย์ไหม) EURUSD ผ่านมาตรฐานแรกแต่ไม่ผ่านมาตรฐานที่สอง

**สรุปรวม CIR ทั้งโปรเจกต์**: ยังไม่มี combination ไหนผ่านทั้ง 2 มาตรวัดพร้อมกัน — EURUSD (ทั้ง M5/M15) มีสัญญาณที่ดีกว่าสุ่มชัดเจนแต่ยังไม่ยืนยัน edge แบบเต็มรูปแบบ, XAUUSD M15 แย่กว่าสุ่มจริง (สัญญาณเตือนว่า CIR อาจไม่เหมาะกับ M15 เลย)

### 27. Config Stability Check + Fixed-Config Walk-Forward บน CIR (EURUSD) — **ยืนยันว่าเป็น overfitting ไม่ใช่ edge จริง**

ตามที่เคยพิสูจน์ให้เห็นผลกับ momentum (experiment 24) ว่า fixed-config walk-forward เป็นการทดสอบความทนทานที่แข็งแรงกว่า re-optimize ทุก fold — ทำแบบเดียวกันกับ CIR บน EURUSD (ตัวที่ดูมีสัญญาณดีที่สุดจาก experiment 26)

**เช็ค config ที่ถูกเลือกในแต่ละ fold**:
- **EURUSD M5** (13 fold): **ไม่มี config ไหนซ้ำเด่นชัด** — `calib_window` กระจายไปทั่ว 40/60/80/120/160 (ตัวที่ชนะบ่อยสุดคือ 60 แค่ 4/13 ครั้ง) มีแค่ `q_mult=1.0` และ `tau_threshold=calib_window` ที่เสถียรทุก fold
- **EURUSD M15** (46 fold): เสถียรกว่ามาก — `calib_window=40` ถูกเลือก 22/46 fold (48%), `k=1.8` ส่วนใหญ่ (61%), `tau_threshold=calib_window` แทบทุก fold

**Fixed-Config Walk-Forward บน EURUSD M15** (`calib_window=40, k=1.8, tau_threshold=40`, config ที่ถูกเลือกบ่อยสุด, ไม่ re-optimize เลยตลอด 46 fold):

```
AGGREGATE (n=1398, 46 fold, config เดียวตลอด):
  win_rate=55.5%  PF=0.85  expectancy=-0.0000918/ไม้  maxDD=0.17
  Bootstrap 95% CI = [-0.000185, -0.000001]  P(mean>0)=0.022
  Monte Carlo: เอาชนะสุ่มได้ 77.6% (ไม่ผ่าน 95%)
```

**ผลตรงข้ามกับ momentum โดยสิ้นเชิง**: ตอน re-optimize ทุก fold, EURUSD M15 CIR ดูเหมือนผ่าน Monte Carlo (98.3%, experiment 26) แต่พอล็อค config เดียวไม่ให้เลือกใหม่ **ผลพังลงเป็น PF 0.85 และ CI ติดลบอย่างมีนัยสำคัญ (P(mean>0)=2.2%)** — ตรงข้ามกับ momentum ที่ fixed-config ยืนยัน/ทำให้ผลดีขึ้น

**สรุป**: นี่คือหลักฐานเดียวกับที่เจอกับ OU ธรรมดาตอนแรก (experiment 19) — **ผลที่ดูดีของ CIR ตอน re-optimize ทุก fold เป็นเพราะได้เลือก config ใหม่ที่เหมาะกับแต่ละ fold พอดีทุกครั้ง (overfitting) ไม่ใช่เพราะมี pattern ที่คงที่จริง** CIR บน EURUSD ไม่ผ่านการทดสอบความทนทานเลย — ยังไม่มีโมเดล/config ไหนในโปรเจกต์นี้ที่ผ่านทั้ง Bootstrap CI, Monte Carlo, และ Fixed-Config Walk-Forward พร้อมกันสักตัว (ยกเว้น XAUUSD M5 momentum ที่ผ่านครบแต่ถูกตัดทิ้งเพราะไม่ใช่ math-derived model)

### 28. GARCH(1,1)-Filtered OU — โมเดลสุ่มตัวที่สาม (math-derived)

หลัง OU (ไม่มีสัญญาณ) และ CIR (สัญญาณบวกแต่ไม่ผ่าน + พังตอน fixed-config) ทั้งคู่ไม่ผ่าน ลองโมเดลที่สาม: **GARCH(1,1)-filtered OU** — drift เหมือน OU/CIR เป๊ะ ต่างที่ noise variance เดินตามสมการ GARCH(1,1) ของ Bollerslev (1986): $\sigma_t^2 = \omega + \alpha\varepsilon_{t-1}^2 + \beta\sigma_{t-1}^2$ (จับ volatility clustering — ช่วงผันผวนมักตามด้วยผันผวนต่อ แทนที่จะขึ้นกับระดับราคาแบบ CIR หรือคงที่แบบ OU)

เพิ่มไฟล์ `analysis/strategies/garch_ou_mean_reversion.py` (`estimate_garch11()` fit ด้วย MLE ผ่าน `scipy.optimize`, `KalmanGARCH` มี sigma2 เป็น live state อัปเดตทุกบาร์จาก innovation ของ Kalman filter เอง) และ `scripts/research/garch_rolling_wfo.py`

**ข้อจำกัดด้านความเร็ว**: GARCH MLE ต้องรัน optimization ทุกครั้งที่ recalibrate ซึ่งช้ากว่า OU/CIR (closed-form) มาก — ต้องลด grid จาก 108 เหลือ 8 config และ `recalib_every` จาก 5 เป็น 20 ถึงจะรันจบใน 30 นาที (แทนที่จะเป็นหลายชั่วโมง)

**ผล XAUUSD M5 (12 จาก 14 fold ใช้ได้ — 2 fold ไม้ไม่ถึงขั้นต่ำ)**:
```
total n=104  win_rate=56.7%  PF=1.36  expectancy=+1.21/ไม้  maxDD=84.12
Bootstrap 95% CI = [-0.86, 3.26]  P(mean>0)=0.879
Monte Carlo: เอาชนะสุ่มได้ 90.2% (ไม่ผ่าน 95%)
folds with PF>=1.0: 7/11 (64%)
```

**เทียบทั้ง 3 โมเดลบน XAUUSD M5**:

| โมเดล | Bootstrap P(mean>0) | Monte Carlo percentile |
|---|---|---|
| OU | ~0% | ~0% |
| CIR | 80.8% | 85.7% |
| GARCH-OU | **87.9%** | **90.2%** |

**แนวโน้มดีขึ้นตามลำดับ OU → CIR → GARCH-OU ทั้งสองมาตรวัด แต่ยังไม่มีตัวไหนทะลุ 95%** — ยังต้องเช็ค fixed-config walk-forward ก่อนเชื่อ (บทเรียนจาก CIR: ผลตอน re-optimize อาจเป็น overfitting เหมือนที่เจอมาแล้ว) และยังไม่ได้ทดสอบ symbol/timeframe อื่นเลย

**Config Stability Check + Fixed-Config Walk-Forward บน GARCH-OU (XAUUSD M5)**: เช็ค config ที่ถูกเลือกใน 12 fold ที่ใช้ได้ — **`calib_window=60` ถูกเลือก 8/12 fold (67%)**, **`tau_threshold=calib_window` เสถียร 100%**, `k=2.2` เป็นส่วนใหญ่ (58%) — เสถียรกว่า CIR บน M5 มาก (ที่ไม่มีตัวไหนเกิน 4/13) ล็อคเป็น fixed config (`calib_window=60, k=2.2, tau_threshold=60`) รันผ่านทุก fold โดยไม่ re-optimize เลย:

```
AGGREGATE fixed-config (n=129, 14 fold ใช้ได้ครบทุก fold):
  win_rate=54.3%  PF=1.28  expectancy=+0.96/ไม้  maxDD=102.54
  Bootstrap 95% CI = [-1.02, 2.84]  P(mean>0)=0.825
  Monte Carlo: เอาชนะสุ่มได้ 87.6%
```

**ต่างจาก CIR อย่างสิ้นเชิง — ไม่ใช่ overfitting**: เทียบ re-optimize (PF 1.36, Bootstrap 87.9%, MC 90.2%, 12/14 fold ใช้ได้) กับ fixed-config (PF 1.28, Bootstrap 82.5%, MC 87.6%, **ใช้ได้ครบทุก fold**) — **ลดลงเล็กน้อยเท่านั้น ไม่ใช่พังกลับทิศแบบ CIR** (CIR ตกจาก MC 98.3%→77.6% และกลับเป็นลบมีนัยสำคัญ) บ่งชี้ว่า GARCH-OU มีความทนทานจริง ไม่ใช่ผลจากการเลือก config ใหม่ที่เหมาะกับแต่ละ fold

**สรุป GARCH-OU**: เป็นโมเดลที่น่าเชื่อถือที่สุดในบรรดา 3 โมเดล (OU, CIR, GARCH-OU) ผ่านการทดสอบความทนทานได้จริง แต่**ยังไม่ถึงเกณฑ์นัยสำคัญ 95%** (82.5-90.2% ทั้งสองมาตรวัด) ยังต้องทดสอบ symbol/timeframe อื่นก่อนสรุปขั้นสุดท้าย

**ทดสอบ GARCH-OU เพิ่มอีก 4 combination (XAUUSD M15, EURUSD M5, EURUSD M15, NDX100 M15)**:

| Symbol | TF | PF | Bootstrap P(mean>0) | Monte Carlo |
|---|---|---|---|---|
| XAUUSD | M5 | 1.36 | 87.9% | 90.2% |
| XAUUSD | M15 | 1.00 | 50.3% (เท่าเดาสุ่ม) | 51.7% (เท่าเดาสุ่ม) |
| EURUSD | M5 | 0.63 | **1.3% (ลบมีนัยสำคัญ)** | 46.6% |
| EURUSD | M15 | 0.70 | **1.5% (ลบมีนัยสำคัญ)** | 14.5% (แพ้สุ่ม) |
| NDX100 | M15 | 0.98 | 43.1% (เท่าเดาสุ่ม) | 57.4% (เท่าเดาสุ่ม) |

**สรุปรวม GARCH-OU ทั้งโปรเจกต์**: **ดีเฉพาะ XAUUSD M5 เท่านั้น** — ทุก combination อื่นแย่กว่าหรือเท่าเดาสุ่มหมด และ **EURUSD ทั้ง 2 timeframe กลับเป็นลบอย่างมีนัยสำคัญ** (ตรงข้ามกับ CIR ที่ EURUSD ดูดีกว่า XAUUSD) — บ่งชี้ว่า GARCH-OU ไม่ใช่โมเดลที่ generalize ข้าม symbol ได้ แต่ละโมเดลเหมาะกับ symbol/timeframe ที่ต่างกันไปแบบไม่มีรูปแบบชัดเจน ยังไม่มีโมเดลไหนในทั้ง 3 ตัว (OU, CIR, GARCH-OU) ที่ผ่านเกณฑ์นัยสำคัญ 95% ในทุก mataริกพร้อมกันสักตัว

### 29. เติม Monte Carlo Baseline ย้อนหลังให้ OU + สร้างกราฟเปรียบเทียบทุกโมเดลครบทุกสินทรัพย์

OU (`rolling_wfo.py`) ทำ rolling WFO มาตั้งแต่ experiment 20-22 แต่ตอนนั้นยังไม่มี Monte Carlo permutation test (เพิ่มเข้ามาทีหลังตอนทำ CIR) — เพื่อเทียบทุกโมเดลบนมาตรฐานเดียวกัน ย้าย `monte_carlo_baseline()` ไปไว้ที่ `rolling_wfo.py` เป็นจุดกลาง (แก้ปัญหา circular import ระหว่าง 3 ไฟล์) เพิ่ม `extract_trades()` ให้ OU แล้วรัน Monte Carlo ย้อนหลังทุก combination ที่เคยทำ พร้อมเพิ่ม CIR บน NDX100 M15 (ไม่เคยทดสอบมาก่อน) ให้ครบ

**ตารางสรุปทุกโมเดล × ทุกสินทรัพย์ (ครบสมบูรณ์)**:

| Symbol | TF | OU Bootstrap/MC | CIR Bootstrap/MC | GARCH-OU Bootstrap/MC |
|---|---|---|---|---|
| XAUUSD | M5 | **95.1% / 97.0%** ⚠️ | 80.8% / 85.7% | 87.9% / 90.2% |
| XAUUSD | M15 | 9.2% / 6.2% | 9.1% / 3.0% | 50.3% / 51.7% |
| EURUSD | M5 | 21.9% / 85.4% | 79.1% / **99.6%** ✅ | 1.3% / 46.6% |
| EURUSD | M15 | 15.2% / 84.8% | 47.7% / **98.3%** ✅ | 1.5% / 14.5% |
| NDX100 | M15 | 49.2% / 70.0% | 80.4% / 93.5% | 43.1% / 57.4% |

**ผลที่น่าตกใจที่สุด**: **OU บน XAUUSD M5 (ผลตัวแรกสุดของทั้งโปรเจกต์ ที่ DSR แบบเก่าเคยบอกว่า ~0%) กลับผ่าน Monte Carlo จริง 97.0%** และ Bootstrap P(mean>0)=95.1% (เฉียดพอดี แต่ CI ยังต่ำกว่าศูนย์เล็กน้อยที่ขอบล่าง เลยยังไม่นับว่า "ผ่านเกณฑ์ CI ทั้งแถบ" อย่างเป๊ะๆ) — ผลลัพธ์เดียวกันทุกประการ (14 fold, PF 1.43, ข้อมูลเดียวกันเป๊ะ) แต่วัดด้วยวิธีต่างกันให้ข้อสรุปต่างกัน (DSR เก่า: ไม่มีนัยสำคัญเลย vs Monte Carlo: ผ่าน 97%)

**ทำไมถึงขัดแย้งกัน**: DSR เก่าที่ใช้ในรอบนั้น (n_trials=64 ต่อ fold, sr_variance จาก pool ของ config ที่ผ่านเกณฑ์) เป็นการประมาณคร่าวๆ ที่ไม่ตรงกับโครงสร้าง rolling WFO เป๊ะ (ตามที่ module docstring ของ `rolling_wfo.py` เขียนเตือนไว้เอง) ส่วน Monte Carlo เทียบตรงกับสุ่มเข้าไม้แบบเดียวกันจริงๆ ไม่ต้องพึ่งสมมติฐานเรื่อง n_trials — **Monte Carlo น่าเชื่อถือกว่าในกรณีนี้** เพราะตรงกับโครงสร้างข้อมูลจริง

**ข้อสรุปสำคัญที่ต้องทบทวน**: ผลที่เคย "ตัดสินใจว่าไม่มี edge" ของ XAUUSD M5 OU (จาก experiment 20 ที่ใช้ DSR) **อาจจะด่วนสรุปเกินไป** — เมื่อวัดด้วย Monte Carlo (มาตรฐานที่ตรงกว่า) มันผ่านจริง 97% แม้ Bootstrap CI จะยังไม่ผ่านเป๊ะ (95.1% vs เกณฑ์ CI ทั้งแถบ) นี่คือ combination ที่ใกล้เคียงกับการพิสูจน์ edge จริงที่สุดในทั้งโปรเจกต์ — **ควรพิจารณา fixed-config walk-forward บน OU XAUUSD M5 ก่อนสรุปขั้นสุดท้าย** (ใช้ pattern เดียวกับที่ทำสำเร็จกับ momentum และ GARCH-OU)

**อื่นๆ ที่น่าสนใจ**: CIR NDX100 M15 (93.5%) ใกล้ผ่านที่สุดในบรรดา NDX100 ทั้งหมด และดีกว่า OU/GARCH-OU บน NDX100 ชัดเจน — ขัดกับที่เคยสรุปไปก่อนหน้าว่า NDX100 "ไม่เหมาะกับ mean-reversion เลย" (บทสรุปนั้นมาจากตอนทดสอบแค่ OU เท่านั้น)

### 30. Config Stability Check + Fixed-Config Walk-Forward บน OU (XAUUSD M5) — **ยืนยันว่าเป็น overfitting เหมือน CIR ไม่ใช่ edge จริง**

ตามคำแนะนำจาก experiment 29 ทำ fixed-config walk-forward บน OU XAUUSD M5 (combination เดียวที่ Monte Carlo ผ่าน 97.0%) ก่อนเชื่อว่าดีขึ้นจริง ใช้ pattern เดียวกับที่ทำสำเร็จกับ momentum (exp 24) และ GARCH-OU (exp 28)

**เช็ค config ที่ถูกเลือกในแต่ละ 14 fold**: ไม่มี config ไหนถูกเลือกซ้ำเด่นชัดขนาด momentum (64%) แต่เห็นแพทเทิร์นบางส่วน — `k=1.8` ถูกเลือก 12/14 fold (86%), `q_mult=1.0` และ `tau_threshold=calib_window` (ไม่เคยเลือก `tau_frac=None`) ถูกเลือกทุก fold (100%), ส่วน `calib_window` แบ่งเป็น 40 (8/14) กับ 80 (5/14) — ชุดที่ซ้ำเป๊ะบ่อยสุดคือ `calib_window=40, k=1.8, q_mult=1.0, obs_noise_scale=0.5, tau_threshold=40` (5/14 fold)

**Fixed-Config Walk-Forward บน XAUUSD M5** (config ข้างต้น ล็อกตัวเดียว ไม่ re-optimize เลยตลอด 14 fold):

```
AGGREGATE fixed-config (n=156, 14 fold ใช้ได้ครบทุก fold):
  win_rate=58.3%  PF=0.92  expectancy=-0.328/ไม้  maxDD=175.95
  Bootstrap 95% CI = [-2.255, 1.581]  P(mean>0)=0.374
  Monte Carlo: real=-51.21 vs random_mean=-17.25 (std=150.23)  real exceeds only 39.7% of random-entry simulations
```

**พังครบทุกมาตรวัด** — เทียบ re-optimize (PF 1.43, Bootstrap 95.1%, Monte Carlo 97.0%) กับ fixed-config (PF 0.92, Bootstrap 37.4%, Monte Carlo 39.7%) **กลับทิศจากบวกเป็นลบทั้งคู่** เหมือนกับที่เกิดกับ CIR บน EURUSD M15 เป๊ะ (exp 27) ไม่ใช่แค่ "ลดลงเล็กน้อย" แบบ GARCH-OU (exp 28) — ยืนยันว่าผลที่ดูดีตอน re-optimize ทุก fold (95.1%/97.0%) เป็น **overfitting จากการเลือก parameter ใหม่ที่บังเอิญเหมาะกับแต่ละ fold** ไม่ใช่ edge จริงที่ทนต่อการล็อก config เดียว

**สรุปสถานะรวมล่าสุดของทั้งโปรเจกต์**: ทดสอบ fixed-config walk-forward แล้ว 3 ครั้ง (momentum, CIR EURUSD M15, OU XAUUSD M5) — **มีแค่ momentum ที่ผ่านเกณฑ์ 95% เต็มรูปแบบ แต่ถูกตัดทิ้งเพราะไม่ใช่ math-derived model** ส่วนโมเดล math-derived ทั้ง 3 ตัว (OU, CIR, GARCH-OU) **ยังไม่มีตัวไหนผ่าน fixed-config เต็มรูปแบบสักตัว** — **GARCH-OU บน XAUUSD M5 ยังคงเป็นผลที่น่าเชื่อถือที่สุด** เพราะเป็นโมเดล math-derived ตัวเดียวที่ทนต่อ fixed-config ได้ (ลดลงเล็กน้อยเท่านั้น ไม่กลับทิศ) แม้จะยังไม่ถึงเกณฑ์นัยสำคัญ 95% ก็ตาม

### 31. Fixed-Config Walk-Forward บน CIR (EURUSD M5, NDX100 M15) — ปิดเคสให้ครบทุกสินทรัพย์: **พังทั้งคู่**

ต่อจาก exp 30 (OU XAUUSD M5 พัง) ทำ fixed-config check ให้ครบกับผลที่ดีที่สุดของอีก 2 สินทรัพย์ที่เหลือ: **CIR บน EURUSD M5** (Bootstrap 79.1%/MC 99.6% ตอน re-optimize) และ **CIR บน NDX100 M15** (Bootstrap 80.4%/MC 93.5%, ผลดีที่สุดของ NDX100 ทุกโมเดล) — ทั้งคู่ยังไม่เคยเช็คมาก่อน

**Config stability**: ทั้งสอง combination ไม่มี config ไหนถูกเลือกซ้ำเด่นชัด (EURUSD M5: ชุดที่ตรงกันบ่อยสุดแค่ 2/13 fold, NDX100 M15: 8/48 fold) — สัญญาณเตือนล่วงหน้าว่าไม่น่าจะทน (ต่างจาก momentum ที่ 9/14=64% และยังผ่านได้จริง)

**CIR EURUSD M5 fixed-config** (`calib=60, k=1.8, obs_noise=1.0, tau=60`, 222 ไม้/13 fold):
```

Bootstrap P(mean>0)=10.2% (เดิม 79.1%)
Monte Carlo: เอาชนะสุ่มได้ 80.0% (เดิม 99.6%)
```

**CIR NDX100 M15 fixed-config** (`calib=40, k=1.8, obs_noise=1.0, tau=40`, 1717 ไม้/48 fold):
```

Bootstrap P(mean>0)=35.1% (เดิม 80.4%)
```

**สรุป**: ทั้งคู่พังเหมือน CIR EURUSD M15 (exp 27) — ตัวเลขที่ดูดีตอน re-optimize ทุก fold (โดยเฉพาะ Monte Carlo 99.6%/93.5% ที่ดูใกล้ผ่านมาก) ยุบตัวลงมาเหลือ 58-80% ทันทีที่ล็อค config เดียว **CIR ไม่ผ่าน fixed-config เลยสักตัวในทั้ง 3 combination ที่ทดสอบ** (EURUSD M15, EURUSD M5, NDX100 M15) — ยืนยันว่า CIR เป็นโมเดลที่ overfit ง่ายเป็นพิเศษ (สอดคล้องกับ config stability ที่กระจายตัวสูงในทุก combination)

**สถานะสรุปครบทั้ง 3 สินทรัพย์ ณ จุดนี้**: ทดสอบ fixed-config walk-forward ครบทุกผลลัพธ์ที่ดีที่สุดของแต่ละสินทรัพย์แล้ว (XAUUSD: OU M5 + GARCH-OU M5, EURUSD: CIR M5 + CIR M15, NDX100: CIR M15) — **มีแค่ GARCH-OU บน XAUUSD M5 ตัวเดียวในทั้งโปรเจกต์ที่ผ่านการทดสอบนี้ได้** (ทนได้จริง แม้ยังไม่ถึงเกณฑ์นัยสำคัญ 95%) ทุกผลลัพธ์อื่นที่เคยดูมีความหวัง (ทั้ง OU และ CIR ทุก combination) พิสูจน์แล้วว่าเป็น overfitting จากการ re-optimize ทุก fold ทั้งหมด

### 34. VaR-Threshold (Empirical Quantile) แทน k×σ บน GARCH-OU — ทดสอบแนวคิดจากภาพที่ผู้ใช้ส่งมา

ผู้ใช้ส่งภาพอธิบาย "VaR Zones" ที่ใช้ percentile ของ error distribution (VaR 90%/99%/10%/1%) แทนการใช้ k×σ เป็นเกณฑ์เข้า/stop — ประเมินแล้วว่าเป็นแค่วิธีนิยาม "ผิดปกติแค่ไหน" แบบอื่น (non-parametric แทน parametric) ไม่ใช่โมเดลใหม่ เข้าเกณฑ์ math-derived ของโปรเจกต์ได้ (VaR เป็นเครื่องมือสถิติมาตรฐาน) เลยลองสร้าง `analysis/strategies/garch_ou_var_mean_reversion.py` (ใช้ empirical percentile ของ residual แทน k×σ_stat) มาเทียบกับ GARCH-OU เดิมบน XAUUSD M5

**รอบแรก (ใช้ percentile 90%/99% ตรงตามภาพ)**: ได้ 6,031 ไม้ (เทียบกับ k×σ เดิม 104 ไม้) PF=0.92, Bootstrap=1.8% (ลบมีนัยสำคัญ), Monte Carlo=17.7% (แย่กว่าสุ่มมาก) — พบว่า percentile 90% หลวมกว่า k=2.2 มาก (k=2.2 ภายใต้สมมติฐาน normal ≈ percentile 98.6%) เข้าไม้ถี่เกินไปมหาศาล ไม่ใช่การเทียบที่แฟร์

**รอบสอง (grid search percentile ให้แฟร์)**: สร้าง `scripts/research/garch_var_rolling_wfo.py` ลอง entry_pctile ∈ (95,97,98,99) × stop_pctile ∈ (99,99.5) รัน rolling WFO เต็มรูปแบบบน XAUUSD M5 — grid เลือก percentile 98-99% เกือบทุก fold (ตามคาด) แต่ผลยังแย่กว่า k×σ มาก:
```
total n=3130  PF=0.90  Bootstrap P(mean>0)=2.7%  Monte Carlo=15.9% (แย่กว่าสุ่ม)
```
จำนวนไม้ยังสูงกว่า k×σ มาก (3,130 vs ~104) แม้ใช้ percentile สูงสุดแล้ว

**สาเหตุทางเทคนิคที่พบ**: `k×σ_stat` ของ OU/GARCH-OU ไม่ใช่ค่าเบี่ยงเบนของ residual ดิบ แต่เป็น **stationary standard deviation** ของกระบวนการทั้งระบบ ($\sigma_{stat}=\sigma/\sqrt{2\theta}$, กว้างกว่า residual เพราะรวมผลแรงดึงกลับ) ส่วน VaR-threshold ที่สร้างคำนวณ percentile จาก **residual ดิบ (one-step prediction error)** ซึ่งแคบกว่ามาก ทำให้ band แคบเกินไปเทียบกับ k×σ_stat แม้ใช้ percentile สูงสุดก็ตาม — เป็นข้อผิดพลาดของหน่วยวัดที่ใช้เทียบ ไม่ใช่ข้อพิสูจน์ว่าแนวคิด VaR ใช้ไม่ได้โดยตัวมันเอง

**สถานะ**: หยุดตรงนี้ตามคำแนะนำ (ผู้ใช้เห็นด้วยว่าไม่คุ้มเวลาไล่แก้ต่อ เพราะต่อให้แก้หน่วยวัดให้ตรงกัน ปัญหาหลักคือความไม่เสถียรของสัญญาณเอง ไม่ใช่ที่วิธีตั้ง threshold) — ไม่สรุปแน่ชัดว่า VaR-threshold ใช้ไม่ได้ แค่ implementation ที่ลองยังไม่แฟร์พอ

### 35. Jump-Diffusion OU — โมเดลสุ่มตัวที่สี่ (math-derived)

หลัง OU, CIR, GARCH-OU ทั้ง 3 ไม่ผ่าน (หรือผ่านแค่บางส่วนแล้วอ่อนลงตอนเช็ค window อื่น) ลองโมเดลที่สี่ตามที่คุยไว้ก่อนหน้า: **Jump-Diffusion OU** — $dX_t = \theta(\mu-X_t)dt + \sigma dW_t + J\,dN_t$ (Merton 1976 jump-diffusion ต่อยอดบน OU drift, ใช้จริงกับราคาพลังงาน/สินค้าโภคภัณฑ์ เช่น Cartea & Figueroa 2005)

สร้าง `analysis/strategies/jump_ou_mean_reversion.py`: `estimate_jump_diffusion()` แยก residual เป็น diffusion vs jump ด้วย threshold `jump_z×std` (ค่าเริ่มต้น 3.5), ประมาณ $\sigma$ จาก residual ฝั่ง diffusion เท่านั้น (ไม่ปนเปื้อนจาก jump แบบที่ OU ธรรมดาเจอ) และเพิ่มกลไกใหม่ 2 อย่างที่ OU/CIR/GARCH-OU ไม่มี: **บล็อกเข้าไม้ถ้าเบี่ยงเบนปัจจุบันเป็น jump เอง** (ถือว่าเป็น structural break ไม่ใช่จังหวะ mean-revert) และ **หยุดไม้ทันทีถ้าเกิด jump ใหม่ระหว่างถือ** (`jump_stop`)

**ผล XAUUSD M5 (48 configs × 14 fold, rolling WFO เต็มรูปแบบ)**:
```
total n=289  win_rate=49.1%  PF=0.76  expectancy=-0.82/ไม้  maxDD=275.60
Bootstrap 95% CI = [-1.88, 0.24]  P(mean>0)=6.2%
Monte Carlo: เอาชนะสุ่มได้แค่ 9.9% (แย่กว่าสุ่มมาก)
folds with PF>=1.0: 5/14 (36%)
```

**แย่ที่สุดในบรรดา 4 โมเดลที่ทดสอบบน XAUUSD M5** (OU MC=97.0% แต่พังตอน fixed-config, CIR MC=85.7%, GARCH-OU MC=90.2%, Jump-OU MC=9.9%) — win rate เฉลี่ยยังพอใช้ได้ (49%) แต่ PF ต่ำกว่า 1 ชัดเจน บ่งชี้ว่าไม้แพ้ใหญ่กว่าไม้ชนะเฉลี่ย น่าจะเป็นเพราะกลไก `jump_stop` ตัดไม้กำไรทิ้งเร็วเกินไปเมื่อเจอ overshoot ปกติที่ดันถูกจัดเป็น "jump" ผิดพลาด (threshold `jump_z=3.5` อาจไวเกินไปสำหรับ M5 ที่มี noise สูง) — ยังไม่ได้ลอง symbol/timeframe อื่นหรือปรับ `jump_z` เพิ่มเติม แต่ผลตั้งต้นแย่กว่าทุกโมเดลก่อนหน้าชัดเจน
